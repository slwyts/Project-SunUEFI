# 源码公开与二进制发布

源码公开和二进制发布是两件事。当前只有源码和 CI 构建产物，没有正式的二进制 Release。唯一产品为 `artifacts/product/PianoUEFI-product.img`；当前能力见[项目状态](../status.md)。

## 公开源码前

* 检查要公开的文件和 Git 历史中是否有个人信息、凭据、设备标识和无权分发的内容。被忽略的目录不代表历史里从未出现过。
* 完成原创代码、第三方库、字体、固件和生成内容的许可与署名清单，见[第三方来源](../../THIRD_PARTY.md)。
* 确认公开的依赖仓库和提交都能取到，并从一份独立克隆检查[目录边界](repository-map.md)和[内核角色](kernel-roles.md)。
* 说明完整构建仍需要哪些本地输入（[本地输入](local-inputs.md)）。

## 发布二进制前

每个发布候选要对应明确的源码、配置、工具、输入材料，以及清单和哈希；构建检查需要通过（`build_integrity.py`、产品检查）。发布说明逐项写出：

* 哪些功能可用，哪些不可用；
* 适用的设备和系统版本；
* 回到 Android 的方法；
* 入口路径：

| 路径 | 发布前要核对 |
| --- | --- |
| 临时 `fastboot boot` | 实际发送的镜像、菜单与后台服务、退出和恢复 |
| 合体 BOOT 启动 Linux | 内核与模块配套、ESP 读取、交接、用户空间、返回 Android |
| Recovery 入口 | 不使用。独立 Recovery 会被 ABL 拒绝，见[返回 Android](../user/recovery.md) |
| 标准 EFI-stub | 内存约定、`ExitBootServices`、运行时服务；与现有 ARM64 原始交接是不同路径 |

## 二进制再分发

提取的原厂固件、原生 PE 和派生模块的二进制再分发条件还没有审查。哈希只能证明身份，不构成发布许可。正式 Release 前要按实际内容核对来源、通知和许可，并做重复构建与设备验证。在此之前，不扩大首页写出的功能声明。
