# 源码公开与二进制发布

源码仓库公开与产品二进制发布分开验收。当前唯一产品为 `artifacts/product/PianoUEFI-product.img`，状态保持 `INCOMPLETE_NOT_RELEASE`；诊断镜像与 OS 载荷用于独立实验，不因重命名而成为另一个已完成产品。当前能力见 [状态](../status.md)。

## 源码公开前

- 复核待公开文件与 Git 历史中的个人信息、凭据、设备标识和无权分发内容；ignored 目录不等于历史从未包含相关材料。
- 完成原创/派生源码、第三方库、字体、固件与生成内容的许可和署名清单。当前仓库及二进制许可归属仍待完整核对，不能以“本地可用”推导可公开分发。
- 确认公开依赖 remote 和必要 commit 可取，并从独立克隆检查 [目录边界](repository-map.md)、[内核角色](kernel-roles.md) 与实际可运行测试范围。
- 明确完整构建仍要求哪些本地输入，以及尚未闭环的首次准备步骤。源码公开可以保留这些限制，不能宣称已完成匿名克隆后的完整复现。

## 二进制候选与正式发布

每个候选绑定 source/base、配置、工具、native 输入与派生身份、FD/BootShim、SimpleInit、DTB、OS Image/initramfs/模块，以及对应 manifest/build-id/hash。`build_integrity.py`、SimpleInit 身份和产品合约检查需要通过；失败构建或失效源码不能通过修改记录复用旧产物。

候选发布说明逐项写明已验收能力、入口、剩余问题、适用设备/版本和回退输入。主机构建通过、fastboot `OKAY`、驱动加载或 RAM 截图各有有限含义，不替代真实启动、传输、画面与恢复验收。

| 入口/路径 | 独立验收要求 |
| --- | --- |
| `fastboot boot` 临时产品 | 实际发送的唯一产品身份、菜单/输入/后台服务与退出行为，随后恢复结果 |
| 本地 ESP 启动 Linux | 实际文件、配套内核/模块、读取来源、所有者退休、交接、用户态与恢复证据 |
| recovery 入口 | 装载与认证接受、正确入口策略、退出和恢复；结构合法的 AVB 容器不等于 ABL 接受，当前仍未闭环 |
| 标准 EFI-stub | EFI 内存契约、ExitBootServices、运行时环境与实际 OS 启动；raw ARM64 成功不能直接继承 |

正式二进制发布还需完成所分发内容的许可、可获取构建输入、重复构建验证和所声明入口的实机验收。未完成时保留候选/未发布标签及具体缺项；不为了开放源码而扩大硬件可用声明。原诊断结果、恢复输入和历史镜像身份继续保留。
