# Linux-managed DMA masters and readback ABI

This independent unit does not edit the frozen complete-DTB builder, existing
kernel candidates, derived rootfs or hardware services. No tablet access,
module load, raw MMIO command or ready marker is performed on the host.

The actual current runtime FDT and352508 source agree on six DMA masters:

| Consumer node | SID/mask | Actual allocation/mapping consumer |
| --- | --- | --- |
| ssusb@a600000 |40/0| Flattened mainline DWC3 parent, moved from vendor nested child |
| ufshc@1d84000 |60/0| UFS HCD |
| qcom,gpi-dma@a00000 |b6/0| QUP1 GPI coherent descriptor/event rings (`gpi.c:1407`) |
| qupv3_1_geni_se@ac0000 |a3/0| SPI `dma_map_dev=dev->parent` and I2C GPI buffer `dma_map_single(parent)` |
| qcom,gpi-dma@800000 |436/0| QUP2 GPI rings |
| qupv3_2_geni_se@8c0000 |423/0| QUP2 I2C/SPI payload buffers |

GPI descriptor and QUP payload devices are different DMA API consumers. Binding
only the GPI controller does not bind the buffers mapped through the wrapper.
`configs/linux/dtb/piano-linux-owned-dma.dtso` retargets only these six iommus
properties to the actual Linux `apps_smmu_ml`, `/soc/iommu@15000000`, with two
provider cells. No provider count, register, clock, GPIO or enable status changes.
`tools/apply_piano_dma_masters.py` uses real cpp/dtc/fdtoverlay/libfdt and rejects
any other property/tree/reservation change. The separate private candidate is
`private/analysis/piano-linux-owned-dma/Piano-full-linux-owned-dma.dtb`,1209139
bytes/SHA256 `7b96afd614fdddbb8916f9ebdcf3876bfac8af8a6ca21f840ccf1c86af7c18f8`.
It has not replaced the existing complete DTB or been staged into rootfs.

## Actual kernel interface

The independent `codex/piano-smmu-routes` kernel worktree starts at1fd91b90a720.
Normal IOMMU probe/default identity-domain attachment allocates or adopts each
master's stream entries. It does not clone USB0x40. The prior safe cfg_probe patch
chooses its own unreferenced disabled emulated bypass CB when required, preserving
live firmware routes. No global SMMU disable or userspace register programming
is used by this unit.

The driver creates a read-only `piano_dma_route` device attribute on each actual
ARM-SMMU-configured master. This is not a file generated by a userspace planner.
The getter requires the driver's real cfg/fwspec and actual ARM identity-domain
attachment. Under its runtime-PM and stream-map locking it reads hardware SMR,
S2CR and, for a translating route used as passthrough, CB SCTLR/CBAR/FSR. Hardware
is compared with kernel-private expected state, including QCOM hypervisor bypass
encoding. Valid/mode/index/fault checks and repeated register equality are
required. Unknown/no binding, nonidentity domain, changed hardware, active
translation or faults return a real read error instead of success text.

Output starts `piano-dma-route-v1 domain=identity ids=N`, then each actual master
SID/mask, stream slot, origin, raw SMR/S2CR/private expected encoding and CB
registers. `origin=kernel-installed` and `origin=firmware-adopted` remain distinct.
Preserving and verifying an existing route for its real consumer is not copying
another USB route or pretending it was newly created. The readback interface
programs no route, clears no fault and grants no RAM permission. Runtime PM may
enable the bound SMMU's normal clock/power resources to perform a safe driver read.

`tools/check_piano_kernel_dma_routes.py` reads the actual sysfs attributes twice
and validates the six expected exact SIDs, masks, identity domain, private versus
hardware encoding, passthrough CB mode and fault status. It supports native
BYPASS and QCOM's TRANS+M0 emulation. It does not accept a ready string, ordinary
status file, synthetic USB ancestor, mismatched privilege field or stale route.
It emits evidence and a nonzero error on failure; **it never writes a marker**.
The platform names follow the selected kernel's `drivers/of/device.c:283..305`
translated-address plus `%pOFn` naming rule and the unchanged final node names.
The verifier also resolves each real `of_node` symlink to the exact final DT
path before reading. Duplicate keys, extra fields, signs, wide register values
and noncanonical numeric representations are rejected. Firmware-adopted output
is explicitly `kernel-attached-inherited-bypass`, never relabeled as a wholly
kernel-installed owner.

## Remaining integration gate

The actual prepare must load matching kernel/master drivers through their normal
IOMMU/PM paths and collect these readbacks before allowing GPI/input/UFS-dependent
services. The public `piano-qup-smmu` USB-ancestor script is incompatible with
strict UEFI retirement and must be replaced; `display-start`'s marker cannot be
satisfied by touching a file. Kernel readback success proves the scoped managed
passthrough routes, not successful DMA, device enumeration, all DSP/PCIe/display
stream requirements, idle external owners, secure MMIO accessibility or full DDR.
The six-master helper does not authorize those other streams. DMA tests, exact
kernel/vermagic, firmware, inherited rails and a reliable EFI memory map remain
separate mandatory facts. All host manifests keep hardware and memory authority
false until real boot evidence exists.

Verification: four host tests exercise native/emulated encodings, healthy FSR
format versus fault, wrong SID/mask/private privilege rejection and actual
six-property overlay application. ARM64 objects are compiled from the real kernel
source; the shared register comparator also runs in the actual handoff C selftest
under ASAN/UBSAN. Neither test class is a tablet hardware observation.
