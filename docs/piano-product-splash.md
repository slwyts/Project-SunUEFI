# Single-product native GOP boot splash

The test92 RAM log establishes that GOP really reached3200×2136 with stride3200
atFC800000, and LogoDxe loaded. It also records BootLogo2 `Not Found` and
`SUNUEFI_PRODUCT_TIANOCORE_SPLASH status=Not Found`. The old enable call did not
prove that the product had rendered a logo; the small visible logo could be an
inherited bootloader framebuffer.

`bootprofiles/product-support/Library/ProductBootManagerLib/ProductSplash.c`
now renders through the actual GOP `Blt` interface from AfterConsole. It has no
BootLogo2/LogoDxe dependency, direct framebuffer pointer, image decoder or bitmap
asset. The reference-inspired six-spoke orange geometric mark and rounded
lowercase `tianocore` wordmark are defined in `ProductSplashAssets.h`, with a
secondary `SunUEFI / Piano` tag. The operation captions use compact built-in
ASCII glyphs. Artwork and pixels are generated by the actual firmware source.

On3200×2136 the mark occupies a427-pixel square on the left of a horizontal logo
group, with the294-pixel lowercase wordmark on its right. The pure-white design
uses orange facets and dark-gray text. BIOS captions are left-aligned at X192
(6% margin), Y1901/Y2007, with35/28-pixel glyph height. Layout
scales with the shorter display dimension; the actual C tests also render800×600
and480×320 and reject unsupported small or excessive dimensions before drawing.

The bottom captions are `F12: BIOS Setup   Esc: Boot Menu` and
`Volume +/-: Navigate   Power: Select / Confirm`. F12 refers to the existing
BootPolicy action/notification path; it does not claim that USB or pogo keyboard
hardware has passed testing. Volume/power correspond to the existing physical
input mapping. GraphicsConsole paints readable black character cells for its
light-gray-on-black attributes; product DEBUG is RAM-only, so white splash needs
no console reconfiguration. Stdout, framebuffer console and RAM logging remain connected.
There is no timer or automatic reset/erase of later diagnostics. The next UI
normally repaints the display when it takes over.

The boot-manager library establishes its ExitBootServices fence once, before
painting and before the product core is started. The renderer checks lifetime
before and after every GOP call; warning/error stops rendering immediately and
reports the actual status. It retains partial pixels as diagnostics rather than
retrying or claiming success. The boot-manager record is now
`SUNUEFI_PRODUCT_SPLASH status=... backend=gop-blt vector=1 ... hint_drawn=...`.

The library INF includes the actual new C/headers and GOP GUID. Existing
`prepare_product.py` copies all `bootprofiles/product-support` files and existing
build freshness hashes that directory, so no Root Core or prepare change is
needed. This is enabled in the same canonical product library, not a separate
GUI test profile.

Validation command:

```sh
python3 -m unittest discover -s tests -p test_product_splash.py -v
```

Actual renderer C runs with the real Mu UEFI types and ASan/UBSan. Tests inspect
large-mode pixels and caption coverage, every Blt rectangle boundary, lower-mode
layout, warnings/errors and EBS fences; the same renderer emits the real PPM
preview. Both renderer and actual boot-manager wrapper pass strict ARM64 syntax.
The other test checks the actual INF, BDS hook and canonical freshness source.

The viewable preview is
`build/previews/product-splash/product-splash-horizontal-3200x2136.png`, losslessly converted
from that C-generated PPM. It is not another mockup. The tablet rendering awaits
Root's next unified image test; a host preview is not physical GOP acceptance.
